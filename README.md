技术全景——AI应用开发核心技术的深度拆解
认知建立后，本篇进入技术腹地。把AI应用开发的核心技术逐个拆开讲透：每项技术解决什么问题、在企业场景中怎么用、学到什么程度算过关。这是整个课程体系的知识骨架。

一、大模型应用开发的思维转换。 学习的第一步是思维转换：把大模型当作一种新型组件来对待。传统组件如数据库负责存取数据、消息队列负责异步解耦，而大模型是一个“理解与生成的引擎”，你输入自然语言（提示词），它输出智能结果。这个视角转换极其重要：它意味着你不需要理解模型的内部原理就能用好它，就像你不需要理解B树的实现也能用好MySQL。但工程视角同时意味着新挑战：传统组件的输入输出是确定的，而大模型的输出是概率性的——同样的问题可能得到不同回答，可能产生幻觉（编造事实），可能被恶意输入诱导。AI应用开发的全部工程难题，本质上都源于这个“不确定性”。理解了这一点，后面所有技术设计的动机就都通了。

二、提示词工程：被低估的核心技能。 很多人以为提示词就是“把问题说清楚”，这是严重低估。生产级的提示词工程是一门严谨的技术：结构化提示词设计（角色设定、任务描述、约束条件、输出格式四要素），少样本示例（给模型看几个标准例子，输出质量显著提升），思维链引导（让模型分步推理而不是直接给答案，复杂任务准确率大幅提升），输出格式约束（强制JSON格式输出，让AI结果可以被程序直接解析处理）。对企业应用来说，提示词就是“新时代的SQL”，写得好坏直接决定AI功能的质量上限。课程中会系统训练这门手艺，目标是：给你一个业务场景，你能设计出稳定、可控、可维护的提示词体系。

三、Function Calling：连接AI与你的业务系统。 这项技术是Java工程师价值兑现的关键枢纽。大模型本身只会聊天，不能查数据库、不能调接口、不能执行业务操作。Function Calling机制让大模型能够“调用”你预先定义好的函数：你告诉模型“你有这些工具可用”，用户提问时，模型判断需要哪个工具、生成调用参数，你的Java代码执行真正的业务逻辑，再把结果交回模型组织成回答。举一个典型场景：用户问“帮我查一下上个月的订单状态”，模型识别意图后调用你写的订单查询函数，拿到数据后生成自然语言回复，这就把大模型变成了企业系统的智能入口。掌握这项技术，你就掌握了AI与万千存量系统连接的桥梁。

四、RAG：企业级AI应用的第一主角。 大模型有两个致命短板：知识截止于训练时间，且不知道你企业的私有数据。RAG（检索增强生成）正是解决方案：把企业文档切分、向量化后存入向量数据库；用户提问时，先把问题向量化、检索出最相关的文档片段，再把这些片段连同问题一起交给大模型生成回答。一句话总结：模型负责“说话”，检索负责“喂料”。工程实现中的关键环节包括：文档解析与切分策略（切太碎丢上下文，切太大检索不准）、向量化模型选型、向量数据库选型、检索优化（混合检索、重排序）、引用溯源（回答必须标注来源，这是企业落地的信任基础）。RAG是企业知识库、智能客服、内部问答系统的标准架构，也是课程项目实战的重头戏。

五、Agent：从“问答”到“办事”的跃迁。 如果说RAG解决了“AI知道”，Agent解决的是“AI会做”。Agent的核心是让大模型获得自主性：接到任务后，它能自己拆解步骤、规划方案、调用工具、检查结果、迭代修正，直到任务完成。比如“帮我分析这份销售报表，找出异常并生成分析报告”——Agent会自主读文件、跑数据查询、调分析工具、写报告。技术实现上，Agent等于“大模型加工具集加任务循环”：模型在循环中不断决定下一步动作，直到给出最终答案。
